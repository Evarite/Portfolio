My C# & Unity Architecture

Code isn't just about getting things on screen—it's about maintainability, testability, and zero allocation in hot loops. Inspect my actual project scripts below.

ScriptableObject Template Method Spawner
Polymorphic ScriptableObject architecture with generics. Decouples entity configuration from spawner logic; allows adding new obstacle/coin spawners without modifying existing managers.
Template Method ScriptableObject VContainer DI Generics <T> 
// Lab.Managers.Spawn.Services.AbstractSpawnService.cs
using Lab.Pooling;
using UnityEngine;

namespace Lab.Managers.Spawn.Services
{
    public abstract class AbstractSpawnService : ScriptableObject
    {
        public abstract void Spawn(PoolService poolService, SpawnContext spawnContext);
    }
}

// Lab.Managers.Spawn.Services.SpawnService.cs
using Lab.Managers.Spawn.Data;
using Lab.Pooling;
using UnityEngine;

namespace Lab.Managers.Spawn.Services
{
    public class SpawnService<TSpawnData> : AbstractSpawnService
        where TSpawnData : SpawnData
    {
        [SerializeField] protected TSpawnData spawnData;

        public sealed override void Spawn(PoolService poolService, SpawnContext spawnContext)
        {
            for (int i = 0; i < spawnData.SpawnCount; i++)
            {
                if (poolService.TryGet(spawnData.Prefab, out var entity))
                    SpawnEntity(entity, spawnContext);
            }
        }

        protected virtual void SpawnEntity(PooledEntity entity, SpawnContext spawnContext)
        {
            float x = spawnContext.PlayerTransform.position.x +
                      Random.Range(spawnData.MinXDist, spawnData.MaxXDist);
            float y = Random.Range(spawnData.MinY, spawnData.MaxY);

            entity.transform.position = new Vector3(x, y, 0f);
        }
    }
}
Engineering Standards

How I Write Unity Code

Architectural principles grounded in real project repositories: verifiable separation of concerns, explicit dependencies, and modular systems.

⚡

Event-Driven Architecture

Decoupling publishers and listeners using C# Action and events. Systems react to state transitions and game over conditions cleanly without polling loops in Update().

💉

Dependency Injection (VContainer)

Declaring explicit system dependencies through LifetimeScope and constructors. Services, pool managers, and spawners are resolved cleanly without relying on monolithic singletons or FindObjectOfType.

🎮

Modern Input System by Default

Using InputActionAsset events with callback contexts, rebinding support, and decoupled input managers to ensure responsive controls across platforms.

⏱️

Execution Lifecycle Discipline

Respecting the exact execution order (Awake, OnEnable, Update, FixedUpdate). Coroutine delays and WaitForSeconds instances are cached to eliminate unnecessary runtime allocations.

📦

Object Pooling & GC Control

Frequent GameObject instantiation and destruction triggers garbage collection hitches. Custom PoolService with IObjectResolver pre-allocates and recycles bullets, enemies, and visual effects.

📐

SOLID & Encapsulation

Writing small, focused classes with private backing fields, decoupled interfaces (IHittable, IDeathHandler), and defensive validation via #if UNITY_EDITOR OnValidate().

🛠️

Data-Driven ScriptableObjects

Externalizing hardcoded gameplay numbers into modular, designer-friendly assets. Wave configurations, loot tables, and spawner presets are balanced instantly without modifying code.
