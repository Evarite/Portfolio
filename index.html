Engineering Standards

How I Write Unity Code

My personal engineering standards and architectural principles for writing clean, scalable, and responsive Unity C#.

⚡

Event-Driven Architecture & DI

I adore combining C# events (Action, event) with Dependency Injection (VContainer). Events allow game systems to react to state changes without tight coupling or polling in Update(), while VContainer manages lifecycles with zero monolithic singletons.

🎮

New Input System Only

I avoid legacy Input.GetKey and messy dual systems. I use clean InputActionAsset events with callback contexts, rebinding support, and decoupled input managers.

⏱️

Execution Lifecycle Mastery

I leverage the exact execution order of Unity methods (Awake, OnEnable, Update, FixedUpdate, LateUpdate). I cache WaitForSeconds in coroutines instead of running state checks in Update().

📦

Object Pooling & Zero GC

Instantiating and destroying GameObjects causes garbage collection stutter. My custom PoolService with IObjectResolver pre-allocates and recycles bullets, enemies, and effects cleanly.

📐

SOLID & Clean Encapsulation

I avoid God Classes. I write small, focused classes with public properties, private backing fields, decoupled interfaces (IHittable, IDeathHandler), and defensive editor validation via #if UNITY_EDITOR OnValidate().

🛠️

ScriptableObject Architecture

I turn hardcoded values into modular, designer-friendly assets. Data-driven configurations for wave spawning, loot tables, and growth stages make balancing instant without code changes.
